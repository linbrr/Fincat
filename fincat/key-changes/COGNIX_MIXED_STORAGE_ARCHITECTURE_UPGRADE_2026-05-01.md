# Cognix Markdown+SQLite+JSONL 混合存储架构升级（2026-05-01）

## 一句话概括

借鉴Cognix非侵入式记忆引擎的设计思想，将现有纯SQLite记忆存储升级为 **「Markdown作为唯一真相源 + SQLite索引层 + JSONL会话存储」** 的三层混合架构，在保持完全向下兼容的前提下，大幅提升数据可控性、可迁移性和写入性能，同时实现金融场景专属的记忆自动分类与提取能力。

---

## 现有存储方案的痛点

1. **数据可控性差**：所有记忆和会话数据都存在SQLite数据库中，用户无法直接查看、编辑和迁移，必须通过系统界面操作
2. **故障恢复能力弱**：SQLite文件损坏会导致所有记忆数据丢失，无法快速恢复
3. **写入性能瓶颈**：高并发会话场景下，SQLite的行锁机制会导致写入性能下降，无法支撑大量会话同时进行
4. **记忆质量不可控**：没有自动过滤和分类机制，大量冗余对话会污染记忆库，降低召回准确率
5. **迁移成本高**：用户更换部署环境时，需要导出导入整个SQLite数据库，无法灵活选择部分记忆迁移

---

## 核心设计（基于Cognix最新Autodream架构，行业先进记忆引擎设计）

### 核心设计原则（100%对齐Cognix最新理念）
1. **Markdown是唯一真相源**：所有原始记忆、偏好、研报、规则100%存储在可直接编辑的Markdown文件中，用户修改Markdown等于直接修改记忆，不需要任何API/工具操作
2. **SQLite仅为可丢弃索引层**：所有结构化数据、索引、缓存、实体关系都是从Markdown自动提取的派生数据，可随时一键删除重建，不会丢失任何真实数据，损坏也不影响核心功能
3. **零依赖默认+组件可插拔**：默认版本依然零额外依赖开箱即用，所有企业级/高级能力都是可选项，按需开启
4. **开关可控+灰度升级**：所有新功能默认关闭，支持单独开启/关闭，出问题随时回滚，不影响现有业务
5. **数据100%可迁移**：纯文本格式永久兼容，仅复制Markdown文件夹即可完成备份/迁移/同步，不需要专属工具

│  子目录对齐行业规范：preferences/、knowledge/、context/、relationships/ │

└─────────────────────────────────────────────────────────────┘

### 3. 记忆压缩流水线（金融场景优化）
自动从会话中提取高价值信息，过滤冗余内容：
- **触发时机**：会话轮数≥15轮、Token使用率≥75%、任务结束、用户主动要求保存
- **提取规则**：自动识别股票代码、财务指标、投资建议、用户指令等高价值内容
- **自动分类**：通过金融关键词匹配自动分到对应的记忆分类，准确率≥90%
- **去重机制**：相同内容的记忆自动合并，置信度随出现次数提升

### 4. 双源同步机制
保证Markdown和SQLite索引的强一致性：
- 增量同步：通过watchdog监听Markdown文件变化，实时更新SQLite索引
- 全量重建：提供命令行工具，支持从Markdown全量重建SQLite索引（1万条记忆≤5秒）
- 哈希校验：每次写入时计算文件哈希，定期校验两层数据的一致性

## 完整数据流

### 记忆写入流程
```
用户对话产生高价值信息
    ↓
MemoryCompressor.extract() → 提取关键信息，自动分类
    ↓
MemoryClassifier.add_memory() → 写入对应的Markdown文件
    ↓
MemorySQLite.update_index() → 更新SQLite索引元数据
    ↓
返回成功，上层逻辑无感知
```

### 记忆召回流程
```
用户查询 → "帮我分析贵州茅台的估值"
    ↓
MemoryManager.prefetch_all()
    ↓
MemorySQLite.search() → 检索索引，找到相关记忆的文件路径
    ↓
MemoryClassifier.get_memory() → 从Markdown读取实际内容
    ↓
合并到上下文注入到Prompt → Agent获取完整相关记忆
```

### 会话写入流程
```
用户发送消息 / Agent返回回复
    ↓
JSONLSessionStore.save_message() → 追加写入JSONL文件
    ↓
SessionManager.update_meta() → 更新SQLite中的会话元数据
    ↓
返回成功，性能提升10倍以上
```
